## Phase 1 — 基础设施(后续命令/能力都依赖)

为后续命令提供缺失的底层能力。纯新增函数 + 少量接线,不动现有逻辑。

**1.1 `saveConfig` 写盘** — `src/services/Config.ts`
- 新增 `saveConfig(partial: Partial<ConfigValue>, scope?: 'user'|'project'): Promise<void>`
- 读现有 config 文件(`configPath()` / 项目级 `.fuckcode/config.json`)→ deepMerge → 原子写(`.tmp`→rename)
- 复用现有 `deepMerge`。当前全项目无写盘函数,这是缺失地基。

**1.2 `deleteMemory`** — `src/instruction/memory.ts`
- 新增 `deleteMemory(cwd: string, name: string): Promise<boolean>`,删 `.fuckcode/memory/<name>.md`
- 当前只有 loadMemories/saveMemory,无删除。

**1.3 MCP 连接传入 Repl** — `src/repl/App.tsx` + `src/repl/Repl.tsx`
- App.tsx:43 把 `connectAllMcpServers` 的 `result.connections` 存入模块级 `let mcpConnectionsRef`(或加 `McpState` 单例模块 `src/mcp/McpState.ts` 暴露 `getMcpConnections()/setMcpConnections()`)
- Repl props 加 `mcpConnections?: McpConnection[]`,命令 handler 可读
- 选用模块级单例方案(避免 App→Repl props 穿透 + resume 后丢失问题)

**1.4 MCP 单 server 管理** — `src/mcp/McpClient.ts`
- 新增 `disconnectOne(connections, name)` / `reconnectOne(config, name)` 辅助函数
- 暴露 connection 健康状态(用 `client.getPing()` 探活)

## Phase 2 — 零接线命令(纯函数直接调)

全部只需 import 现有纯函数 + 读 `configRef`/`chatHistoryRef`,改 `Repl.tsx`(ALL_COMMANDS 数组 ~51-75 + register 块 ~1075-1341)。每个命令两处都加。

**2.1 `/compact`** — 手动触发上下文压缩
- 复刻 `queryLoop.ts:215-258` 逻辑:调 `compactConversation(chatHistoryRef.current, {model, apiKey, signal})` → `writeCompactBoundary(sessionId, cwd, summary)` → 替换 `chatHistoryRef.current` 为单条 boundary message → setHistory 提示
- 无 sessionId 时提示用户。加 `{ requiresRunning: false }`

**2.2 `/memory`** — 查看/增删记忆
- 无参:`loadMemories(cwd)` 列出所有(name/type/description)
- `add <name> <type> <content>`:调 `saveMemory`
- `delete <name>`:调 Phase 1.2 的 `deleteMemory`

**2.3 `/hooks`** — 查看 hook 配置
- `loadHooks(cwd)` 展示各事件(PreToolUse/PostToolUse/UserPromptSubmit)的 hook 列表(matcher/command/timeout)
- 标注 `SessionStart` 当前未触发(见 Phase 5)

**2.4 `/status`** — 一屏状态汇总
- 当前模型 / permissionMode / context 用量(estimateMessagesTokens 占 contextWindow 比例)/ token 累计(totalTokensRef)/ MCP 工具数 / 会话 id
- 纯读取展示

**2.5 `/doctor`** — 环境诊断
- 检查:apiKey 是否配置、apiBaseUrl 可达性(可选轻探)、Bun 版本、是否 TTY、.fuckcode/ 目录、config 文件可读、AGENTS.md 是否存在、MCP 配置数
- 每项 ✅/⚠/❌ 列表

**2.6 `/review`** — 代码审查
- `git diff` 取本次会话改动(复用 `handleDiffCommand` 的 diff 获取逻辑)
- 把 diff 喂给当前模型做 PR 式审查(调 `queryLoop` 或一次性 `streamAnthropic`),输出问题/建议
- 无改动时提示

## Phase 3 — 需接线命令(依赖 Phase 1)

**3.1 `/mcp`** — 管理 MCP server(依赖 1.3/1.4)
- 无参:列出连接的 server(name / 工具数 / 健康状态),读 `McpState.getMcpConnections()`
- `reconnect <name>` / `disconnect <name>`:调 Phase 1.4 函数,更新 McpState
- `tools <name>`:列出某 server 的工具清单

**3.2 `/permissions`** — 查看/改权限规则(依赖 1.1 saveConfig)
- 无参:展示 mode + allow/ask/deny 三组规则(读 `configRef.current.permissions`)
- `add <allow|ask|deny> <规则>`:改 configRef + 调 `saveConfig` 持久化
- `remove <allow|ask|deny> <序号>`:同上
- `mode <default|acceptEdits|plan|bypass>`:切模式 + 持久化

**3.3 `/add-dir`** — 多目录工作区
- Repl 加 `extraDirsRef = useRef<Set<string>>(new Set())`
- 改 Read/Glob/Grep/Bash 的 cwd 解析:工具的 ToolContext.cwd 支持多目录(或维护一个 `workspaceDirs` 列表,Glob/Grep 跨目录搜,Read 按绝对路径)
- 最小实现:`/add-dir <path>` 把目录加入集合,Glob/Grep 遍历所有目录,Bash cwd 不变
- `/add-dir` 无参列出当前工作目录集合

## Phase 5 — 能力层中小补齐

**5.2 rewind 对话回滚** — `src/services/Session.ts` + `src/repl/Repl.tsx`
