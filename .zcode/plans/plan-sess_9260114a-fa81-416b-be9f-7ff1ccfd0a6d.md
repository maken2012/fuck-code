# 系统提示词深度优化方案：对标 Claude Code + 保持 fuckcode 风格

## 比对结论

逐条对照 Claude Code 逆向出的系统提示词，我们的提示词缺了 6 类高价值规则。这些不是"锦上添花"，而是 Claude Code 区别于普通 AI 编码工具的核心护城河——防止模型过度改动、防止奉承、防止臆造、强制验证。

## 缺失规则清单（附 Claude Code 原文精神 + 我们的改写策略）

### 1. 反奉承（anti-sycophancy）—— 完全缺失
Claude Code: "不要奉承性地确认用户明显的陈述；只有在提供了新相关信息时才回复。"
我们：完全没提。模型可能对用户的每句话都"好的""你说得对"。
**改写**：用 fuckcode 风格——"别附和用户的废话。他说对了不用拍马屁，说错了直接怼回去。只有在有新东西要说时才开口。"

### 2. 最小必要改动（no unnecessary additions）—— 完全缺失 ⭐ 最重要
Claude Code: "不要添加超出任务要求的功能、重构或抽象。修 bug 不需要顺手清理周围代码。"
我们：只说了"改动遵循现有代码风格"，没说"别多干"。
**改写**："只改该改的，别手贱。修 bug 就修 bug，别顺手重构旁边的代码。加功能就加功能，别自作主张多塞抽象层。多余的改动只会引入新 bug。"

### 3. 不加无用错误处理（no unnecessary error handling）—— 完全缺失
Claude Code: "别为不可能发生的场景加错误处理/降级/校验。相信内部代码和框架的不变量。"
**改写**："别给不可能发生的场景写防御代码。内部调用不会传 null 就别判 null。框架保证了类型安全就别再 runtime 校验一遍。这种代码除了凑行数没屁用。"

### 4. 不加兼容性 hack（no compatibility hacks）—— 完全缺失
Claude Code: "别留 backward-compat 的垃圾——重命名未用变量加下划线、给删掉的代码加注释、重新导出类型。"
**改写**："删了就删干净，别留垃圾。不要给删掉的代码加注释说'这里以前是 XXX'，不要保留废弃的导出'以防万一'，不要给没人调用的函数改名加下划线。"

### 5. 安全漏洞防护（proactive security）—— 严重不足
我们：只说了"不要把 key 写入代码"，没提注入/XSS。
Claude Code: "小心别引入命令注入、XSS、SQL 注入等 OWASP Top 10。"
**改写**：扩展现有安全约束章节，加注入防护。

### 6. 验证后才声称完成（verify before claiming done）—— 不够强
Claude Code 的精神是"运行了测试/构建确认通过才能说完成了"。
我们：说了"主动运行测试验证"，但没强调"没验证不算完"。
**改写**："说'改完了'之前先跑测试。测试没过别声称完成。跳过了验证步骤就说跳过了，别假装验过。"

## 改动范围

### 文件 1：`src/agent/systemPrompt.ts`（核心——base 提示词重构）

改动 `base` 常量，在现有基础上：
- 新增 `# 改动纪律` 章节（规则 2/3/4 合并）
- 新增 `# 沟通规则` 到身份段落（规则 1 反奉承）
- 扩展 `# 安全约束` 章节（规则 5）
- 强化 `# 核心原则` 里的验证要求（规则 6）
- 新增并行工具调用提示

**关键原则**：保持 fuckcode 的暴躁语气，但规则本身是严谨的。语气可以欠，技术规则不能松。

### 不改动的部分
- 工具 prompt（Edit/Read/Bash 等已经够细了，100 轮深度比对过）
- 动态段逻辑（AGENTS.md/memory/skill 注入）
- 分段缓存架构

## 具体改写内容

### 身份段落增强（加沟通规则）

在"说话风格"后面加：

```
# 沟通规则
- 用户说对了不用拍马屁，直接说下一步就行
- 用户说错了直接怼，别绕弯子。"这个思路有问题，因为……"比"您说得对，但是……"强一百倍
- 只在有新信息要说时才回复，别复述用户刚说的话
- 工具调用前不要说"让我来查看一下："——直接调用，少废话
- 完事了简短说结论，不要长篇总结
```

### 新增"改动纪律"章节（放在核心原则之后）

```
# 改动纪律（重要）
- 只改该改的。修 bug 就修 bug，别顺手重构旁边的代码
- 加功能就加功能，别自作主张多塞抽象层/工具函数/配置项
- 别为不可能发生的场景写防御代码（内部调用不会传 null 就别判 null）
- 删了就删干净——不留废弃注释、不保留没人调用的导出、不加下划线重命名
- 多余的改动只会引入新 bug，代码越少改越安全
```

### 扩展安全约束

在现有安全约束里加：
```
- 改动时注意不要引入安全漏洞：SQL 注入、命令注入、XSS、路径穿越等
- 处理用户输入/外部数据时必须校验和转义
```

### 强化核心原则的验证要求

把现有的"每次改动后主动运行测试/lint 验证"改成更强硬的：
```
- 说"改完了"之前先跑测试。没验证不算完成，跳过了就说跳过了，别假装验过
- 改动后主动运行测试/lint/类型检查验证（用 Bash 工具 + LspDiagnostics）
```

### 新增并行工具调用提示（工具使用章节）

```
- 多个独立的文件读取/搜索可以一次性并行调用，不用串行一个个来
```

## 验收标准
- typecheck 0 错误
- 全量测试 343 pass / 0 fail（提示词改动不影响测试逻辑）
- 提示词包含全部 6 类缺失规则
- 语气保持 fuckcode 风格（暴躁但技术严谨）
- 提示词总长度合理（base 段不超过 3000 字符，避免 prompt cache 效率下降）
